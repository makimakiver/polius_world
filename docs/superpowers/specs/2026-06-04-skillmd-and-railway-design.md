# SKILL.md boot-load + Railway deployment + env-based signing key

**Date:** 2026-06-04
**Status:** Approved (design)

## Problem

Two goals:
1. Run the Pollius scheduler/heartbeat on a host like Railway.
2. Externalize Hermes's skill prompt into an editable `SKILL.md` that the agent loads
   on boot ("boot up according to the instruction").

Surfaced along the way: the signing key currently loads from a *file*
(`HERMES_KEYPAIR_FILE`), which doesn't fit Railway (secrets are env vars, not files),
and the Hermes agent shells out to the `sui` CLI, which isn't in Railway's default
image.

## Decisions

- **SKILL.md:** a single `SKILL.md` at repo root; `HermesRegistry` loads it at boot.
- **Key:** generated by a `keygen` CLI and stored in `.env` as `HERMES_KEYPAIR`
  (the `suiprivkey1…` string). No key file.
- **keygen safety:** refuses to overwrite an existing non-empty key unless `--force`.
- **Boot gate:** fail-fast with guidance if `HERMES_KEYPAIR` is missing/empty.
- **Railway:** long-lived worker; `Dockerfile` builder that also installs the Sui CLI;
  run-forever via env (`HEARTBEAT_MAX_CYCLES=0`, `HEARTBEAT_CRON=* * * * *`).

## Components

### SKILL.md (new, repo root)

YAML-style frontmatter + markdown body:

```
---
name: invent-move-primitive
description: Invent a NEW, in-canon Sui Move primitive, build it, and prepare it for on-chain deployment to testnet.
---

You are a citizen of Pollius. Invent ONE new, in-canon Move primitive …
```

The body becomes `Skill.prompt`; `name`/`description` come from frontmatter. Content is
the exact prompt currently hardcoded in `registry.ts`.

### `src/hermes/registry.ts` (modify)

- Remove the hardcoded `INVENT_MOVE_PRIMITIVE` constant and `SKILLS` array.
- Add `parseSkillMd(raw: string): Skill` — a tiny no-dep parser: requires a leading
  `---\n…\n---` frontmatter block, reads `name:` and `description:` lines, treats the
  remaining body (trimmed) as the prompt. Throws if `name`, `description`, or body is
  empty.
- `HermesRegistry` constructor takes `skills: Skill[]` (no default).
- Add `static async load(file = resolve("SKILL.md")): Promise<HermesRegistry>` that
  reads + parses the file and returns `new HermesRegistry([skill])`.
- Keep the exported inert `READ_PRIOR_WORK` placeholder unchanged.

### `src/keygen.ts` (new) — `pnpm keygen`

- Generate `Ed25519Keypair.generate()`.
- `secret = keypair.getSecretKey()` (bech32 `suiprivkey1…`); `address =
  keypair.getPublicKey().toSuiAddress()`.
- Read `.env` (treat missing as empty). If it already contains a non-empty
  `HERMES_KEYPAIR=…` line and `--force` is not passed → print a refusal message and
  exit non-zero.
- Otherwise write the key: replace an existing `HERMES_KEYPAIR=` line if present, else
  append `HERMES_KEYPAIR=<secret>` (with a trailing newline).
- Print the address and the testnet faucet hint.

### `src/config.ts` (modify)

- Remove `keypairFile`.
- Add `keypairSecret: string`, read from `HERMES_KEYPAIR` via a dedicated check that
  throws a guidance message naming `pnpm keygen` when missing/empty. (This is the
  boot gate — surfaced through the existing `main().catch`.)

### `src/executor/executor.ts` (modify)

- Replace `loadKeypair(file)` with `keypairFromSecret(secret: string): Ed25519Keypair`
  — decode the `suiprivkey` string, assert ED25519, return the keypair.

### `src/agent/hermesAgent.ts` (modify)

- Add `/\.env\b/i` to `FORBIDDEN_COMMAND_PATTERNS` — the key now lives in `.env`, and
  the agent's sandbox is `.workdir`; block bash commands that touch `.env`.

### `src/index.ts` (modify)

- `import "dotenv/config";` first (loads `.env` locally; no-op when absent).
- `const keypair = keypairFromSecret(cfg.keypairSecret);` (sync).
- `registry: await HermesRegistry.load()`.
- Otherwise unchanged (scheduler wiring + signal handlers from the prior feature).

### `Dockerfile` (new)

- Base `node:22-bookworm-slim`.
- Install the Sui CLI from a pinned prebuilt release (`ARG SUI_VERSION`,
  `…/releases/download/${SUI_VERSION}/sui-${SUI_VERSION}-ubuntu-x86_64.tgz`), extract
  the `sui` binary to `/usr/local/bin`.
- `corepack enable` + activate pnpm.
- Copy manifests, `pnpm install --frozen-lockfile`, copy source, `CMD ["pnpm","start"]`.

### `railway.json` (new)

```json
{
  "$schema": "https://railway.com/railway.schema.json",
  "build": { "builder": "DOCKERFILE", "dockerfilePath": "Dockerfile" },
  "deploy": { "startCommand": "pnpm start", "restartPolicyType": "ON_FAILURE", "restartPolicyMaxRetries": 10 }
}
```

### `package.json` (modify)

- Scripts: add `"start": "tsx src/index.ts"` and `"keygen": "tsx src/keygen.ts"`.
- `"engines": { "node": ">=22" }`.
- Dependencies: add `dotenv` (`^16`).

### `.env.example` (modify)

- Remove the `HERMES_KEYPAIR_FILE` / `.secrets/hermes.key` block.
- Add `HERMES_KEYPAIR=` with a comment: run `pnpm keygen` to populate, then fund the
  printed address.

### `README.md` (modify)

- Replace the file-key setup steps with `pnpm keygen`.
- Add a "Deploy to Railway" section: Dockerfile builder, env vars to set
  (`ANTHROPIC_API_KEY`, `HERMES_KEYPAIR`, `SUI_NETWORK`, `HEARTBEAT_CRON=* * * * *`,
  `HEARTBEAT_MAX_CYCLES=0`), and a note that `SUI_VERSION` in the Dockerfile may need
  bumping.

## Out of scope

- Multiple skills / a `skills/` directory (single `SKILL.md` by decision).
- Auto-generating a key on boot (explicitly rejected — fail-fast instead).
- Persisting run records to Walrus (still the `NoopStorage` seam).
- Securing `.env` beyond the bash-pattern block (the agent sandbox already restricts cwd).

## Testing

- `pnpm typecheck` passes (validates `Ed25519Keypair.getSecretKey()` /
  `keypairFromSecret` API usage).
- `pnpm test` — existing scheduler tests still pass.
- `parseSkillMd` is pure and unit-testable: add a test that a well-formed SKILL.md
  parses to `{ name, description, prompt }` and that a body-less / frontmatter-less
  input throws.
- Manual: `pnpm keygen` on a repo with no key writes `HERMES_KEYPAIR` and prints an
  address; a second run without `--force` refuses.
